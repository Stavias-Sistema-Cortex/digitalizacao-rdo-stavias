# Cortex 3.0 Institutional Workspace UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make authenticated Cortex tabs use the available viewport with a consistent serious institutional system, truthful data states, responsive density, and accessibility.

**Architecture:** A shared workspace shell owns full-width layout, compact headers, sub-navigation, status rail, scroll region, and dialog bounds. Existing tabs migrate incrementally without changing their domain repositories; frontend policy tests prohibit fake data and assistant affordances.

**Tech Stack:** React 19, TypeScript 6, CSS/container queries, Vitest/Testing Library, in-app browser verification.

## Global Constraints

- Preserve the existing sidebar and information architecture.
- Use Poppins with restrained weights, black/graphite structural accents, and 2/4/6 px geometry.
- Color communicates semantic state/actions, not decoration.
- No sample KPI/card/person/worksite/service/revenue or false sync state in production.
- Empty/loading/offline/error states are data-driven and literal.
- WCAG AA contrast, visible focus, semantic landmarks, keyboard access, and reduced motion.
- Required viewports: 1440×900, 1280×720, 390×844.
