# Cortex 3.0 RDO Workflow and Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create RDOs from real worksites, carry forward the previous workforce with editable apontador, work fully offline, and export truthful two-sheet workbooks matching the supplied model.

**Architecture:** Extend the existing `/api/rdos/contexto` capability with versioned creation provenance and price-aware service choices. A worksite-first client dialog creates a UUID-backed local draft; the backend resolves the authoritative RDO number and Apache POI generates the server workbook, while `@e965/xlsx` implements the same mapping offline.

**Tech Stack:** Spring Boot/JDBC/PostgreSQL, React/TypeScript/IndexedDB, Apache POI 5.3, `@e965/xlsx` 0.20.3, Vitest, Testcontainers.

## Global Constraints

- The worksite must be authorized and selected before the editor opens.
- Client UUID is stable online/offline; server number collision never duplicates the RDO.
- Workforce source is the most recent non-cancelled RDO before the selected date.
- Workers are keyed by collaborator ID; names are snapshots, not identities.
- No `custoRealizado` or `custoHora` in Cortex 3 RDO requests/responses/UI.
- XLSX cells contain persisted values or blanks; never inferred/fabricated operational data.
- Template source SHA-256 is `2a97db997d939b738146bad7c39428e38e159a6160f23afdf3297500fb2b8f87`.
